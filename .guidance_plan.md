# Guidance AI Copilot — Implementation Plan

## Problem
AI copilot shows generic, repetitive popups like "You're running bash commands repeatedly..." even when the user is idle. The AI doesn't know what the user actually did.

## Root Causes

### Cause 1 — Terminal observation sends NO command text
TerminalProvider.observe() only captures session metadata (shell name, session ID, is_ssh flag) — **not the actual commands typed**. The AI gets "TerminalCommand: bash" not "user ran `history | tail -n 15`". It's guessing from nothing.

### Cause 2 — Skill KB matching is broken
`match_observations()` does substring match on raw strings like `"TerminalCommand: bash"`. This never matches skill content about Kubernetes, MySQL, etc. The AI receives zero relevant expertise.

### Cause 3 — No dedup/cooldown between AI ticks
Every 30s the AI runs, produces near-identical suggestions when the same observations repeat. Old cards are dismissed but content is never tracked for dedup.

---

## Phase 1 — Terminal Command Capture (HIGH PRIORITY)

**File:** `src/observation/src/terminal.rs`

**What to do:**
- In TerminalProvider.observe(), add logic to capture actual command text
- Use `bash -c "history 20"` or read from tmux/pty multiplexers
- Include the last 5-10 commands in the observation payload as `command_text` field
- Also capture working directory from `/proc/<pid>/cwd`

**Payload format change:**
```json
{
  "session_id": "...",
  "shell": "bash",
  "command_text": "cd ~/wikilabs-ai-copilot && cargo build\n",
  "working_dir": "/home/khopu/wikilabs-ai-copilot"
}
```

## Phase 2 — Cooldown & Dedup (HIGH PRIORITY)

**File:** `src-tauri/src/api_server.rs` (guidance loop, ~line 1000-1193)

**What to do:**
- Add `last_suggestion_hash: Mutex<String>` to track previous AI response
- Add `last_suggestion_time: Mutex<Instant>` for cooldown
- Before displaying, compute content hash — skip if >80% similar (use simple prefix/substring match)
- Minimum 60s gap between suggestions (configurable)
- Add cooldown tracking to GuidancePanel struct

## Phase 3 — Fix Skill Matching (MEDIUM PRIORITY)

**File:** `src-tauri/src/skill_knowledge.rs`

**What to do:**
- Build a "context profile" from actual activity: extract technology keywords (git, docker, nginx, mysql, python, rust, k8s, etc.) from observed command text, file extensions, URLs
- Match skills against the **context profile**, not raw observation strings
- Return matched skills with relevant excerpts

## Phase 4 — System Prompt Update (MEDIUM PRIORITY)

- Add stronger conversational tone examples
- Make it clear: be specific or don't suggest at all

## Phase 5 — Knowledge Pack Injection (LOW PRIORITY)
